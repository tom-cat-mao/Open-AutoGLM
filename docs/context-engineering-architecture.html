1. 核心循环中的 Context 生命周期

Plan Node

  • select_plan_context() 选择有效 section
  • build_plan_context_block() 构建 inject block
  • compact_messages_for_request() 请求级压缩
  • _build_reflection_context() 反思上下文注入
  • 组装 context_block + marks_block 到 user message
↓ action_parsed + context_metrics ↓

Execute Node

  • _context_update() 更新 action_outcome_summary
  • sanitize_context_payload(consumer="trace_payload") 脱敏手势 trace
  • MessageBuilder.remove_images_from_message() 剥离历史图片
  • 重建完整 messages 列表（replace mode）
↓ action_result + screen_belief 更新 ↓

Reflect Node — Context 状态更新核心

  • build_screen_belief() — 屏幕信念（regex 脱敏 summary）
  • build_action_outcome_summary() — 动作结果摘要
  • update_failure_memory() — 有界失败记忆（最近 N 条）
  • update_summarized_history() — 压缩历史（budget 裁剪）
  • update_gui_memory() — GUI 短期记忆（visited/tried/scroll/progress）
  • detect_repeated_failure() — 重复失败检测
  • sanitize_context_payload(consumer="reflect_prompt") — 反思 prompt 脱敏
↑ context_updates 写回 AgentState → 下一轮 Plan 读取 ↑

2. 三种 Context 模式

Off

context_mode="off"
  • 不收集任何上下文
  • select_plan_context() 返回空 section
  • 不构建 context_block
  • reflect 不更新 context state

Observe（默认）

context_mode="observe"
  • 收集并记录 section IDs
  • 更新 screen_belief / failure_memory / history
  • 不构建 context_block
  • 策略：observe_only
  • 用于 trace/eval 可观测性

Inject

context_mode="inject"
  • 收集 + 构建 + 注入 context block
  • build_plan_context_block() 生成有界 JSON block
  • 注入到 plan node 的 user message
  • 策略：inject_redacted_block
  • 所有字符串经 regex 脱敏

3. Consumer-Aware 分层脱敏架构

核心原则：state 写入路径只做 regex 替换，不做 stub；stub 策略仅在 checkpoint egress 由 RedactingSerializer 触发。

Raw State

原始数据（含敏感信息）

reflection, action_result, visible_text...

→
sanitize_context_payload()
Consumer 路由

根据 consumer 参数选择策略

CONSUMER_POLICY

→
policy 分发
脱敏输出

regex 替换 或 key-level stub

取决于 consumer 类型

Consumer 策略 调用位置 脱敏行为 task_context 支持
"inject" regex build_plan_context_block(), observation.py 所有字符串 regex 替换敏感模式为 <redacted>；不做 key-level stub 是 — 匹配 task 敏感值替换为 <matches_task_value>
"reflect_prompt" regex reflect_node 构建 action_str / result_str 同 inject；regex 替换 是 — 同上
"trace_payload" regex execute_node 手势 trace 脱敏 regex 替换；不做 stub 否
"default" regex 未指定 consumer 时的默认 regex 替换 否
"checkpoint" stub RedactingSerializer 在 checkpoint egress PRIVATE_CONTEXT_TEXT_KEYS 替换为 {redacted, length, sha256}；其余 regex 否

4. Context Block 构建流水线

Step 1: Section 选择 — select_plan_context()

遍历 CONTEXT_SECTION_IDS（11 个 section），调用 _section_has_value() 判断每个 section 是否有信息量。

  • off 模式：返回空 section 列表
  • observe 模式：返回 section IDs，不构建 block
  • inject 模式：返回 section IDs + 构建 context block

11 个 section：screen_belief, last_action_outcome, failure_memory, summarized_history, short_term_memory, action_ledger, gui_memory.visited_screens, gui_memory.tried_actions, gui_memory.scroll_memory, gui_memory.task_progress, grounding_observation

Step 2: Block 构建 — build_plan_context_block()

从 raw state 字段直接读取，组装 6 个组件：

  • screen_belief：current_app + summary（regex 脱敏）+ loading/unsafe/confidence
  • last_action_outcome：step_count + action + success + result_message（regex 脱敏）+ verdict/cause/strategy
  • latest_failure_memory：最近 1 条失败记录（regex 脱敏 current_app）
  • summarized_history：压缩历史字符串（budget 裁剪 + regex 脱敏）
  • gui_memory：visited_screens / tried_actions / scroll_memory / task_progress（regex 脱敏）
  • grounding_observation：grounding 上下文（regex 脱敏）

每个组件经 _context_block_value_is_informative() 过滤，空值/默认值不进入 block。

Step 3: Budget 裁剪 — trim_text()

按 DEFAULT_CONTEXT_BUDGET 逐组件裁剪：

  • screen_belief_summary_chars = 300
  • summarized_history_chars = 800
  • failure_memory_items = 3（block 内取最近 1 条）
  • context_block_chars = 1500（整体 block 上限）

超限截断并标记 context_truncated=True。

Step 4: 请求压缩 — compact_messages_for_request()

仅压缩传给 model_client.request() 的消息副本，不修改 state["messages"]：

  • 剥离所有历史消息中的图片（仅保留最新 user message 的截图）
  • 按 request_recent_messages=6 裁剪消息条数（保留 system + 最近 N 条）
  • 计算 before/after 字符数和近似 token 数

Step 5: Prompt 组装 — plan_node

将 context_block 注入 user message 文本：

  • 首轮：task + screen_info + marks_block + context_block
  • 后续轮：screen_info + reflection_context + marks_block + context_block

最终发送给 VLM 的消息 = compact_messages_for_request() 输出的压缩副本。

5. 脱敏机制详解

5.1 Regex 内联替换 — redact_context_text()

使用 SENSITIVE_PATTERN 正则匹配并替换为 <redacted>，保留周围文本结构。适用于所有 consumer，是默认脱敏手段。

模式匹配内容示例
手机号1[3-9]\d{9}13812345678 → <redacted>
邮箱[\w.+-]+@[\w-]+...user@example.com → <redacted>
订单号(?:订单|order)[\s:#：-]*[A-Za-z0-9-]{4,}订单号: ABC-1234 → <redacted>
验证码(?:验证码|code)[\s:#：-]*\d{4,8}验证码: 123456 → <redacted>
API Key(?:api[_-]?key|token|secret)[\s:=：]+...api_key=sk-abc → <redacted>
JWTeyJ[A-Za-z0-9._-]+\....eyJhbG... → <redacted>
Base64[A-Za-z0-9+/]{120,}={0,2}长 base64 字符串 → <redacted>

5.2 Key-Level Stub — 仅 Checkpoint Consumer

当 consumer="checkpoint" 时，PRIVATE_CONTEXT_TEXT_KEYS 中的键值被替换为摘要 stub：

{ "redacted": true, "length": 42, "sha256": "a1b2c3d4e5f6" }

PRIVATE_CONTEXT_TEXT_KEYS（21 个键）：

visible_text, observed_text, raw_text, chat_content, text, label, value, title, subtitle, address, captcha, verification_code, account, payment_info, message, text_hint, target_text_hint, result_message_summary, final_message, error, reflection

SAFE_CONTEXT_TEXT_KEYS（17 个键，checkpoint consumer 下保留为 regex 脱敏）：

summary, current_app, confidence, action, action_metadata, reflection_verdict, failure_cause, suggested_strategy, summarized_history, screen_id, mark_id, provider, provider_input_hash, raw_screenshot_hash, failure_code, last_verdict, sha256

注意：checkpoint consumer 下，不在 SAFE_CONTEXT_TEXT_KEYS 中的未知 key 一律 stub，宁可多脱敏不漏脱。

5.3 Task-Aware 脱敏 — <matches_task_value>

当 consumer="inject" 或 consumer="reflect_prompt" 且提供 task_context 时，先从 task 文本中提取敏感值，在 payload 中匹配替换为 <matches_task_value>，再做 regex 脱敏。这样 VLM 知道某值来自任务本身，而非泄露。

5.4 Trace 脱敏 — sanitize_for_trace()

JsonlTraceWriter 使用独立的 SENSITIVE_KEYS（完全替换为 <redacted>）和 PRIVATE_TEXT_KEYS（替换为 length+sha256 stub）。与 sanitize_context_payload 是并行体系，用于 JSONL trace 文件输出。

6. 外部边界脱敏

Checkpoint Egress

RedactingSerializer（checkpoint/serde.py）

  • 包装 LangGraph JsonPlusSerializer
  • dumps() 时调用 sanitize_context_payload(consumer="checkpoint")
  • PRIVATE key → stub；其余 → regex
  • loads() 透传（checkpoint 已含 stub）
  • 不改变内存中的 state — 仅在序列化边界脱敏

Trace Egress

JsonlTraceWriter（graph/trace.py）

  • sanitize_for_trace() 独立脱敏体系
  • SENSITIVE_KEYS → <redacted>
  • PRIVATE_TEXT_KEYS → {redacted, length, sha256}
  • 写入 .traces/{trace_id}.jsonl

Mark Registry Prompt Block

MarkRegistry.prompt_block()（graph/marks.py）

  • Mark.to_trace_dict() 使用 consumer="checkpoint"
  • text_summary 被 stub 替换，防止原始屏幕文本泄露到 VLM prompt
  • prompt_block 只输出 mark_id / role / source / confidence / stub

Grounding Provider Hints

observation.py

  • 本地 provider：可接收 raw hints（allow_raw_hints=True）
  • 远程 provider：必须经 _redact_provider_hints() 脱敏
  • 所有 hint 文本经 sanitize_context_payload(consumer="inject")
  • Provider result 的 text_summary 同样经 inject consumer 脱敏

9. 关键不变式

#不变式说明
1 State 写入只 regex，不 stub 所有 state 写入路径（reflect/execute/plan）只做 redact_context_text() 内联替换；key-level stub 仅在 consumer="checkpoint" 时触发
2 compact 不改 state compact_messages_for_request() 只压缩传给 model_client.request() 的消息副本；state["messages"] 不受影响
3 Context 不绕过 HITL context block 是"信念，非授权"；不能通过 context 注入绕过 confirm_node / takeover_node
4 单一 prompt 版本 仅支持 context_harness_v1；get_prompt_version() 对其他版本 fail-closed
5 Grounding fail-closed target-required grounding 失败不得回退为主 VLM 坐标 Tap；只能 fail/等待/接管/重新观测
6 Raw hint 不入 trace/prompt 本地 provider raw hint 可在内存使用，但不进入 trace/checkpoint/prompt/report；远程 provider raw hint 必须显式 opt-in
7 messages_reducer 双模式 plan_node 返回新增消息（append）；execute_node 返回完整重建列表（replace）
8 select_plan_context 不改 state 只产出 section IDs、context block 与计数指标；不修改 Action IR、HITL、pending_execute 等
9 Context block 标注信念 block 标题明确标注"仅为信念，不代表授权"，防止 VLM 将 context 误解为执行授权
10 Stub 策略保守 checkpoint consumer 下，不在 SAFE_CONTEXT_TEXT_KEYS 中的未知 key 一律 stub，宁可多脱敏不漏脱

10. 端到端数据流总览

/* 一轮完整循环中的 Context 数据流 */ Plan Node │ ├─ 1. get_context_mode(state, config) → context_mode ├─ 2. select_plan_context(state, mode) │ ├─ off → ContextSelectionResult(strategy="off") │ ├─ observe → ContextSelectionResult(strategy="observe_only", sections=[...]) │ └─ inject → build_plan_context_block(state) → ContextSelectionResult(block="...", strategy="inject_redacted_block") ├─ 3. 组装 user message: task + screen_info + marks_block + context_block ├─ 4. compact_messages_for_request(full_messages, selection) │ ├─ 剥离历史图片（保留最新截图） │ ├─ 裁剪至 request_recent_messages=6 │ └─ 计算 before/after metrics ├─ 5. model_client.request(compacted_messages) → response └─ 6. 返回 context_metrics → state 更新 Execute Node │ ├─ _context_update() → action_outcome_summary ├─ sanitize_context_payload(gesture_trace, consumer="trace_payload") ├─ MessageBuilder.remove_images_from_message() └─ 重建 messages 列表（replace mode） Reflect Node │ ├─ build_screen_belief() → screen_belief (regex 脱敏 summary) ├─ build_action_outcome_summary() → action_outcome_summary ├─ update_failure_memory() → failure_memory (bounded) ├─ update_summarized_history() → summarized_history (budget trimmed) ├─ update_gui_memory() → gui_memory (visited/tried/scroll/progress) ├─ detect_repeated_failure() → hit/repeated counts ├─ sanitize_context_payload(action, consumer="reflect_prompt", task_context=task) └─ 返回 context_updates → state 写回 /* 外部边界 */ Checkpoint Egress: RedactingSerializer.dumps() → sanitize_context_payload(consumer="checkpoint") → stub Trace Egress: JsonlTraceWriter.emit() → sanitize_for_trace() → stub/redact Prompt Block: MarkRegistry.prompt_block() → Mark.to_trace_dict(consumer="checkpoint") → stub Provider Hints: build_mark_provider_hints() → sanitize_context_payload(consumer="inject") → regex
