Grounding 架构文档

Open-AutoGLM Grounding 系统：从截图到可执行动作。基于 Mark 的 Fail-Closed 流水线，将语义规划与 UI 元素定位解耦。

MarkProvider 协议 Hint-Aware Fallback Fail-Closed 0-1000 归一化坐标 更新日期: 2026-06-17

总览

Grounding 是将主 VLM 的语义意图（如"点击 Wi-Fi 开关"）翻译为设备屏幕上可执行像素坐标的过程。Open-AutoGLM 实现了基于 Mark 的 Fail-Closed Grounding 架构，核心规则如下：

  • ! 主 VLM 绝不输出原始坐标，屏幕目标动作只引用 target_mark_id。
  • ! 所有屏幕定位必须通过 MarkRegistry，由 MarkProvider 实例填充。
  • ! Grounding 失败（Provider 缺失、低置信、过期 Mark、Hash 不匹配、歧义等）绝不回退为主 VLM 原始坐标，直接 Fail-Closed。
  • i 推荐配置 PHONE_AGENT_GROUNDING_PROVIDER=hybrid：优先 Accessibility Tree，LocateAnything VLM 作为 Fallback。
  • + 所有坐标归一化为 0-1000 范围，绝对像素转换仅在 Tool/Backend 层执行。
核心原则：Grounding 是 Tap / Double Tap / Long Press 的唯一输出来源。主 VLM 原始坐标被拒绝。这就是 Fail-Closed 保证。

Mark Provider

所有 Provider 实现定义在 phone_agent/grounding/provider.py 的 MarkProvider 协议：

class MarkProvider(Protocol):
    name: str
    version: str
    def provide_marks(
        self,
        screenshot: Any,
        screen_binding: ScreenBinding,
        hints: list[MarkProviderHint] | None = None,
        timeout: float | None = None,
    ) -> MarkProviderResult: ...
AccessibilityTreeProvider

name="accessibility_tree" · allow_raw_hints=False

  • 解析 Android UiAutomator XML Dump 为归一化 0-1000 Marks
  • 过滤条件：enabled + visible + (clickable | focusable | checkable | long-clickable | scrollable | 文本承载交互类)
  • Mark ID 前缀：ax_
  • 置信度：clickable/focusable 为 1.0，其余为 0.8
  • 按 (bbox, role, text_summary) 去重
  • 默认最大 Marks 数：80
LocateAnythingMLXProvider

name="locateanything_mlx" · allow_raw_hints=True

  • 基于 LocateAnything-3B-4bit 的 VLM 视觉定位，运行在 Apple Silicon MLX 上
  • 按 Hint 逐个运行：每条 Hint 描述生成一个目标 Mark
  • Mark ID 前缀：la_
  • 单 Hint 多框 = grounding_ambiguous Fail-Closed
  • 支持 Parallel Box Decoding (pbd_generate)
  • 默认 max_size=960, context_max_chars=0
FallbackMarkProvider

name="fallback" · allow_raw_hints=True

  • 按顺序运行 Provider；首个成功且可用的结果即停止
  • Hint-Aware 可用性门控：检查 token 在 role/text_summary/source 上的匹配
  • 首个 Provider 的 Marks 不匹配 Hint 时，继续下一个
  • 收集链上所有 Marks；返回合并结果及 fallback_chain 元数据
  • 对 allow_raw_hints=False 的 Provider 脱敏 Hint
FakeGroundingProvider

name="fake" · allow_raw_hints=True

  • 确定性测试替身，返回配置的 BBox
  • Mark ID 前缀：fake_
  • 可配置 failure_code 用于测试错误路径
  • 在 self.requests 中记录所有请求

Hint-Aware 可用性门控

Fallback 链的关键设计决策。没有它，AccessibilityTreeProvider 总是返回 Marks（因为它 Dump 所有可交互元素），LocateAnything 永远不会运行。门控算法如下：

  1. 若无 Hint：任何成功返回 Marks 的结果即为可用 → 停止
  2. 若有 Hint：对 Hint 术语进行分词（按非字母数字/CJK 边界拆分，保留 ≥2 字符的 token，CJK 生成 bigram，最多 12 个唯一术语）
  3. 检查是否有 Hint 术语出现在 Mark 的 role、text_summary 或 source 中
  4. 若匹配：Marks "可用" → 停止 Fallback
  5. 若不匹配：收集 Marks 但 Fallback 继续到下一个 Provider
示例：Hint "点击 Wi-Fi" → tokens ["点击", "wi", "fi", "wifi"]。Accessibility Tree 返回蓝牙、显示、存储的 Marks。无 token 匹配 → 不可用 → LocateAnything 以 Hint "Wi-Fi" 运行 → 返回目标 Mark。

Hint 隐私

allow_raw_hints=False 的 Provider（当前仅 AccessibilityTreeProvider）接收脱敏后的 Hint。脱敏流程：

  • 所有 Hint 字段经 sanitize_context_payload() 脱敏（手机号、邮箱、API Key 等）
  • text 截断至 240 字符，source/action 截断至 64 字符
  • allow_raw_hints=True 的 Provider（LocateAnything、Fake）仅在内存中接收原始 Hint
  • 原始 Hint 绝不进入 Trace、Checkpoint、Prompt Marks Block、Eval JSON 或报告

MarkRegistry 与屏幕身份

Mark 数据结构

每个 Mark 是一个 Trace 安全、屏幕绑定的 GUI 元素引用：

class Mark(frozen):
    mark_id: str          # 如 "ax_1", "la_2_1"
    screen_id: str       # SHA-256 截断至 16 位十六进制
    bbox: tuple[...]       # (x1, y1, x2, y2)，0-1000 范围
    center: tuple[...]     # (cx, cy)，0-1000 范围
    source: str           # "accessibility_tree" | "locateanything_mlx" | "fake"
    confidence: float     # 0.0 - 1.0，阈值 = 0.3
    role: str | None       # 如 "Button", "EditText"
    text_summary: str | None # 脱敏文本，最长 32 字符

屏幕身份系统

MarkRegistry 使用三层屏幕身份系统检测过期 Mark：

层级字段计算方式用途
语义层semantic_screen_idSHA-256("app|WxH")同一应用 + 分辨率
拓扑层mark_set_versionSHA-256(排序后的 "mark_id:bbox:role:source")同一组 UI 元素
感知层perceptual_hash8x8 灰度差异哈希 (64-bit)视觉相似的屏幕

Mark 绑定验证要求三层全部匹配。感知哈希使用汉明距离，阈值 ≤8。

Prompt Block 生成

MarkRegistry.prompt_block() 方法生成注入 VLM Prompt 的文本：

** Screen Marks (use target_mark_id; do not guess coordinates) **
- ax_1: role=Button source=accessibility_tree confidence=1.0 text_summary=OK
- ax_2: role=EditText source=accessibility_tree confidence=0.8 text_summary=Search
- ax_3: role=Switch source=accessibility_tree confidence=1.0 text_summary=Wi-Fi
- la_1_1: role=None source=locateanything_mlx confidence=0.9 text_summary=None
隐私保护：text_summary 在进入 Prompt Block 前通过 sanitize_context_payload(consumer="checkpoint") 脱敏。任意屏幕文本（手机号、邮箱等）会被正则替换。

评分公式

# 综合评分权重
localization = 0.7 * mean_iou + 0.3 * click_accuracy
coverage     = 0.8 * required_recall + 0.2 * optional_recall
final_score  = 0.55 * localization + 0.25 * coverage + 0.20 * text_score

匹配逻辑

  • 主匹配：IoU ≥ 0.5 → 接受匹配
  • 小元素 Fallback：中心命中 + IoU ≥ 0.1 → 适用于小型 UI 控件
  • 贪心一对一匹配（不重复计数）

核心不变式

  • ! Fail-Closed：Grounding 失败绝不回退为主 VLM 原始坐标。只有 target_mark_id 能产生 Tap/Double Tap/Long Press。
  • ! Provider 隔离：LocateAnything/Fake/OCR/UIAutomator/SoM 只能生成 Marks，不能直接产生可执行 ActionIR。
  • ! 原始 Hint 边界：原始 Hint 仅保留在 Provider 内存中，绝不进入 Trace、Checkpoint、Prompt Marks Block、Eval JSON 或报告。远程 Provider 原始 Hint 需显式 opt-in。
  • ! 坐标归一化：所有 Mark 使用 0-1000 相对坐标。绝对像素转换仅在 Tool/Backend 层通过 convert_relative_to_absolute() 执行。
  • i Tree-First Hybrid：PHONE_AGENT_GROUNDING_PROVIDER=hybrid 优先运行 Accessibility Tree。仅当 Tree Marks 不匹配当前 Hint 时才调用 LocateAnything。
  • i 去重抑制：Hybrid Provider 激活时，跳过直接基础 Accessibility Mark 注入。Hybrid 链统一管理 Accessibility Marks，避免重复 ADB Dump 和 Mark ID 冲突。
  • i Mark 绑定：三层身份检查（语义 + 拓扑 + 感知哈希）防止过期 Mark 被执行。
  • + Prompt 模板：LocateAnything 必须使用 apply_chat_template(..., num_images=1)。默认 Instruction 保持极简。Context 注入受 locateanything_context_max_chars 约束。
  • + 多框 Fail-Closed：单 Hint 产生多个 BBox = grounding_ambiguous。不执行首框。
  • + 敏感度门控：Mark 文本中的支付/登录关键词触发 confirm/takeover 中断，即使 Grounding 成功。
