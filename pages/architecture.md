# 架构

## Thin-loop v2：一句话

模型每轮观察真实设备、决定**一个**工具调用、执行**一步**；harness 只做工具、安全边界、上下文卫生和可观测性。**没有工作流路由，没有节点编排**——判断全在模型，规矩全在壳里。

```
┌──────────────────────────────────────────────┐
│ 模型 ← 系统提示 + TaskDoc + 流程线 + 截图/marks │
│   │                                          │
│   └─ 一个工具调用（tap/type/launch/locate/…）   │
│       ↓                                      │
│  工具层（坐标换算/安全门/执行）                  │
│       ↓                                      │
│  原子观测（新截图+marks，epoch+1）              │
│       ↓                                      │
│  回执回流给模型 → 下一轮                        │
└──────────────────────────────────────────────┘
```

## P0 约束（不可违反的设计红线）

| 域 | 约束 |
|---|---|
| 坐标 | 0-1000 相对坐标 → 绝对像素的换算**只在工具内部**发生；模型永远看不到绝对像素 |
| Marks-first | 执行动作必须绑定 mark；目标描述解析不唯一即 fail-closed |
| 图片卫生 | 历史截图滚动剪除（默认保留最新 2 张）；工具成功时总是回传新图 |
| 安全预警 | 风险执行调用先警告不执行，模型带 `confirm_irreversible=true` 重发才真正执行（wary 默认） |
| 工具 fail-closed | 失败返回错误字符串，绝不执行动作或假报成功 |
| Trace 脱敏 | 文本 >64 字截断、敏感子串脱敏、截图 base64 永不落盘 |
| 设备访问 | 一律经 DeviceFactory → ADB 封装，无裸 ADB 调用 |
| 配置 | CLI > shell env > .env > 默认；无硬编码端点/密钥/参数 |

## 原子观测生命周期（U1）

`session.observe()` 是**唯一观测生产者**：一个采样窗口内取齐 前台组件 → 截图 → accessibility dump（复用同一张截图）→ 前台组件复核；窗口内前台变化 = 帧不一致，重试一次，再不稳则观测失败。

每次成功观测 bump `epoch`，所有 mark id 带**批次徽章** `ax_1@e3`——上一批次的 mark 在下一次观测后**自动过期**（`resolve_mark` 新鲜度闸门，过期即拒绝）。这从机制上杜绝了"marks 是一帧、像素是另一帧"的错位（TOCTOU）。

## 上下文工程

| 机制 | 作用 |
|---|---|
| TaskDoc 任务板 | 模型自维护的任务计划，pinned 进每次调用，压缩免疫 |
| 流程线 | 最近 8 步"意图→工具→结果"的台账，从 transcript 纯推导 |
| 图片剪除 | 只保留最新 2 张含图消息（`PHONE_AGENT_IMAGE_KEEP`） |
| Token 预算 | 累计 input+output token 硬上限（默认 1M），耗尽即终止 |
| 两级 auto-compact | 0.75 窗口预警写板收尾；0.92 生成结构化 handoff 折叠历史 |

## 安全与完成

- **安全预警制**（wary）：见[安全模式](safety.md)
- **finish 两段式**：先给复核包（世界事实+路线+疑点），`confirm=true` 才定稿
- **独立验收器**：高风险目标由独立上下文的 verifier 复核（只看目标+证据+尾部截图，fail-open）
